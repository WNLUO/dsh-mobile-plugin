# 手机扩展：作者须知

> 这份文档给**写扩展的人**看，不是给 App 的开发者看。这里讲技术约束：包长什么样、能干
> 什么、怎么跟 App 说话、怎么调试。
>
> 这份文档随 `dsh-mobile-plugin` 的 npm 包一起发布，所以作者装完插件就能在本地读到，
> 不必去找仓库。里面出现的相对路径都以插件包根目录为准。
>
> 安装、回退、能力确认这些是 App 自己负责的事，用户装上之后看得见；你这边只要把包做对。
> 哪些能力要用户点头，见第 4 节。
>
> 一句话流程：写一个普通 DSH 插件，在它的 `package.json` 里声明 `dshMobileExtensions`，
> 把扩展目录放进插件包，发到 npm 或你自己的仓库 → 用户自己装这个插件 → 手机从他那台电脑
> 把包拉下来。我们不审、不登记，也没有提 PR 这一步。

## 0. 先给「帮你写的那个 AI」看这一段

扩展页就是**一个普通网页前端**：随便什么框架、随便什么构建，只要最终产物是一个目录、
里面有 `index.html`。它跑在手机的一个网页内核里，不是 React Native，也拿不到原生能力 ——
所以别在这里用 `react-native`、`expo`、任何原生模块。

要它一次做对，把下面这段原样贴给它（改掉最后两处）：

```
我要给 DSH 手机的「扩展页」写一个网页前端，请你按这些约束做，不要自己发明：

1. 它是一个普通网页，最终产物必须是一个目录：入口固定叫 index.html，其余资源用相对
   路径引用，全部在目录里（不许外链 CDN、不许引 npm 上的 CDN 地址）。
2. 跑在手机 WebView 里，从 file:// 加载。所以：Web Worker 起不来；fetch 只能命中同目录；
   读不到包外的文件。localStorage / sessionStorage 是可用的。
3. 不要用 react-native / expo / 任何原生模块 —— 这里没有原生层。
4. 外壳（标题栏、返回键、右侧动作位）由 App 画，页面里不要再画一条顶栏或返回键。
   页面占满顶栏以下的区域，高度用 100%；内容是长列表就自己滚。
5. 日夜配色：不要自己写死两套颜色。App 会往 <html> 上写 data-dsh-theme="light|dark"，
   同时注入一组 CSS 变量 --dsh-theme-background / -surface / -border / -text /
   -text-secondary / -text-muted / -primary / -danger（值都是 #rrggbb）。你的样式用这些
   变量，切档就跟着变。
6. 要读电脑上的数据，写 window.ReactNativeWebView.postMessage 发一条
   { kind: 'fetch', id, service, path, method }，App 会把响应递回来；声明了 hostData 之后
   直接 fetch 相对路径也会自动走这条路。细节见文档第 5.5 节，我不会再解释一遍。
7. 要 App 替你办事（例如打开一条新对话），发 { kind: 'action', id, action, params }，
   动作名只能从 App 允许的那几个里挑，不能自己造。
8. 根目录要附带一份 manifest.json：{ name, version, apiVersion: "1", main: "index.html",
   capabilities: [...] }。要整页自绘（不要 App 那条顶栏）就再加 "chrome": "bare"，那时
   顶部状态栏那一截要自己用 --dsh-safe-top 让开，出口自己画（点了发 { kind: 'close' }）。
   要浮在对话页那张卡片里、能横滑划开侧栏，加 "placement": "panel"。

产物目录我会放到：<你的插件包里 extensions/<包名>/ 这个位置>
我要做的功能是：<一句话说清>
```

## 1. 扩展是什么

一个目录 + 一份 `manifest.json`，装进手机里跑在一个网页内核里。它不是 App 的一部分：

- **最短的起步是一份现成样例**：`docs/extension-sample/` 里有两个文件（`manifest.json` +
  `index.html`），能装、能跑、能取数、能让 App 办事。把它整份拷走，改里面的字就是你的扩展。
  从零开始写没有必要 —— 那些「第一次总会踩到」的地方（配色、顶栏、跟 App 说话）里面都摆好了。

- **不进 App 的构建**。扩展有自己的构建入口、自己的版本号，跟 App 发版互不牵连。
- **不是 npm 包**。手机上没有 node，装不了任何包管理器里的东西；产物就是那堆文件本身。
- **不是原生代码**。原生组件、原生模块、系统能力都用不上（下面第 4 节说怎么绕）。

## 2. 包长什么样

```
manifest.json      自述：id / name / version / apiVersion / 可选 capabilities
index.html         入口页，固定叫这个名字
libs/…             你自己的库、样式、字体，相对路径引用
```

- **入口页固定是 `index.html`**。`manifest.json` 里没有 `main` 这一项，写了也不读 —— 手机
  打开扩展时找的就是包目录下那一层 `index.html`。宿主在列包时会检查它在不在，缺了整个包
  不会出现在清单里，别等装到手机上才发现打不开。
- **整个目录原样落盘**。清单里的 `path` 就是落盘路径，`index.html` 里用相对路径引用
  同目录的文件；别指望「拍平到一个目录」或者「从别处按绝对路径拿」。
- **自包含，不许外链**。注释、脚本、样式、字体都得在包里。页面加载时是不透明源，
  外部 CDN 一律被 CSP 挡掉。
- **文件清单带 size 与 sha256**，装的时候逐个核对。改一个字节就是一次新的安装。

### 2.0 自带顶栏：不要 App 那条通用栏（`chrome: "bare"`）

扩展页默认会被套上一条 App 的通用顶栏：左边返回键、中间标题、右边动作区。绝大多数扩展
用它就对了 —— 你不用自己画返回键，也不用管状态栏让位。

但有一类页面**整页都是自绘界面**（无限画布就是），它自己有一整套贴着状态栏的工具条。
再叠一条通用顶栏就是两层、白占 44dp，两套返回键还会打架。这种就在 `manifest.json` 里写：

```json
"chrome": "bare"
```

三条要知道的：

- **不写 = 带通用顶栏**，写歪了也按带顶栏处理（多一条顶栏比少一条后果轻得多）。
- **不画顶栏，返回就归你**。App 那颗返回键一起没了，你必须自己提供出口 —— 协议里加了一条
  `{ kind: "close" }`，页面发它就退出这一页（见第 5 节）。安卓物理键与 iOS 边缘滑动仍然
  有效，但那对很多人不够，**别只靠它们**。
- **状态栏让位也归你**：不带顶栏之后，顶部安全区不再有人替你让。用外壳给的
  `var(--dsh-safe-top, env(safe-area-inset-top))` 给页面顶部留出那一截。

### 2.05 侧栏的左右滑动开合要不要（`swipe`）

侧栏能靠「手指从边上往里滑」拉出来，与在对话页里一样。**缺省就是允许**，不用声明。

页内自己有横向手势的扩展（画布要平移、相册要翻页、表格要横滚）需要关掉它 —— 外层那条
手势一抢，用户看到的是「侧栏滑出来、页面同时卡住」：

```json
"swipe": "off"
```

- **不写 = 允许**，写歪了也按允许处理。扩展页与对话页长在同一张卡片里，用户在对话页能划开
  侧栏、换个扩展页划不动，读起来是「这一页坏了」；真会被手势冲突伤到的页面少得多，让它们
  自己声明更省事。
- 停的只是「横滑开合侧栏」那一段，**右边界拖条改宽不受影响**，平板侧栏那颗汉堡按钮也照常能用。

### 2.02 这页长在哪儿（`placement`）

扩展页默认**推一屏**：占满中间那一列，平板上的左右栏会被盖住。多数扩展这样是对的
（「这是另一个地方」）。但有两种页面不是这个语义：

```json
"placement": "panel"
```

| 写法 | 长在哪儿 | 侧栏 | 适合谁 |
| --- | --- | --- | --- |
| 不写 / `"screen"` | 推一屏，占满中间一列 | 盖住 | **缺省**。「我要一整块独立的地方」 |
| `"panel"` | **浮在对话页那张卡里** | 露着，能横滑开合 | 「这是同一块地方的另一份内容」 |
| `"sidebar"` | 右侧栏里（与「目录」那格同一个地方） | 本就属于侧栏 | 「一边看对话一边用它」 |

**`panel` 是「对话页那个壳」**：页面浮在对话页那张圆角卡片里，不是盖在 App 上的一整块。
所以手机上一根手指从边上划能把侧栏拉出来、平板上侧栏一直露着 —— 与你在对话页里的手感一致。
代价是这一页**只在对话页那一屏存在**：退出对话或切到设置 / 统计这类屏栈页，它跟着一起让开。

四条要知道的：

- **`panel` 与 `sidebar` 都不画 App 顶栏的返回键**。这两档的返回由你自己提供 ——
  想给出口就画一颗，点了发 `{ kind: "close" }`（见第 5 节）；不画也行，靠系统返回键与
  边缘手势。**App 只提供能力，画不画由你定。**
- **`panel` 不是保活档**：关掉就真卸载，再打开是一次新的加载 —— 与 `screen` 档一样，
  别指望页面状态替你留着（要留就存进 `storage`，见第 5.7 节）。
- **页面里的横向手势要自己让路**：这一档侧栏横滑是开着的（见 2.05）。若你的页自己也要
  横滑（平移画布、左右翻页），声明 `"swipe": "off"`，否则那条手势会被外层抢走。
- **写歪了按 `screen` 处理**：改缺省会悄悄改掉所有已装扩展的行为，所以缺省刻意保守。

### 2.1 需要 IndexedDB 的页面：声明一个自己的来源（`pageOrigin`）

绝大多数扩展从本地文件加载就够了。但有一类不行：它要把大量内容按站点存起来（IndexedDB），
而 `file://` 上那套不保证可用 —— 画布（无限画布）就是这一类，它整个库都活在 IndexedDB 里。

这种扩展在 `manifest.json` 里加一格：

```json
"pageOrigin": "https://canvas.dsh.local/"
```

- **只认这一个形状**：`https://<名字>.dsh.local/`。名字是小写字母、数字、横线，最长 40。
  不收公网域名、不收 http、不收带端口或路径的写法 —— 这一格是给你一个稳定的站内身份，
  不是让页面挂到某个真实站点上。
- **这个域名就是你的库身份**。改了它等于换一个空库，用户存的东西就找不到了。所以定下来之后
  别动；`https://<名字>.dsh.local/` 里的名字建议就是你的 slug。
- 声明之后，**你那一版必须是一份自包含的 `index.html`**（脚本、样式全内联进去）。因为那个
  域名根本没有服务器，App 是把 HTML 内容读进来、配上这个域名挂起来的。
- 写歪了不报错，只是退回本地文件加载 —— 于是 IndexedDB 那套可能用不了，表现为「存了没留住」。

**能用 `file://` 就别加这一格。** 它是一份「我需要按站点存东西」的声明，不是默认选项。

**导航是自动认的，不需要登记任何东西。** 声明了 `pageOrigin` 之后，App 会把「指向你这个
本源、以及它下面任何站内路径」的跳转都留在页面里（`/canvas/abc`、`?x=1`、`#hash` 都算），
**只有真的往外走的外链才交给系统浏览器**（官网、GitHub 这类照常能点开）。

这条判据是按「这个地址是不是你自己的」算的，不认识具体哪个扩展 —— 所以你不用申请、不用
等我们加白名单，声明了就自动生效。反过来说，**别指望它当成外链跳板**：到了别的域名就是
别的域名，会被交出去。


## 3. 从本地文件加载：这几条跟你熟的那个浏览器不一样

装进来的扩展是 `file://` 加载的，不是 `http(s)://`。这不是配置问题，是「页面从哪儿来」
决定的：

- **本地存储可用**。`localStorage` / `sessionStorage` 都开着，放心用它们记界面偏好。
  早期版本只给声明了取数的那种扩展开，2026-11-11 起一律打开 —— 那层限制封不住想干坏事的
  人（页面能拿到的东西，一张图片照样能带出去），只挡住作者正当的用法。
- **真 Worker 起不来**。`importScripts` 会报 NetworkError。要 worker 就把它的代码当普通
  脚本引进来、在主线程上跑一个假 worker（Office 那份 pdf.js 就是这么做的）。
- **`fetch` 本地资源受限**，`blob:` 地址同理。资源要么在包里、要么让 App 递给你。
- **页面被锁在它自己那个版本目录里读文件**，读不到包外的任何东西。

### 3.1 最后一条只对「装进来的那份」成立

开发的时候可以不这样：在开发目录那份额外写一格

```json
"devServer": "http://192.168.1.5:5288"
```

手机上的那一页就会**直接加载这个地址**（而不是本地文件），于是页面自己的热更新就生效了 ——
改完保存，手机上当场变，不用等构建、也不用重装。

三条要知道的：

- **只认私网与回环地址 + http**（`192.168.*` / `10.*` / `172.16–31.*` / `127.0.0.1` /
  `localhost` / `*.local`）。写公网地址、https、带路径或查询串，一律当没写。JS 收窄一次、
  手机再收一次。
- **要同一个 Wi‑Fi，并且开着那个开发服务器**（端口要与清单里写的一致）。连不上会**自动
  退回本地那份**，不是白屏 —— 但那时你看到的是上一次同步过来的版本。
- **这一格只对本地开发包生效**。正式装进来的扩展永远跑你装的那一份，不会被远程内容顶掉。
- 开发服务器得监听所有网卡（`vite --host` / `--host 0.0.0.0`），只听 `127.0.0.1` 的话
  手机拨过去指的是它自己。

## 3.5 在右侧栏占一个入口（可选）

带界面的扩展可以不从设置里进：在 `manifest.json` 里写一段 `entry`，用户装上之后，
**右侧栏的入口条末尾**就会多出这一格，点开直接是扩展自己的那一页。

```json
"entry": { "name": "生图工作流", "slot": "normal", "icon": true }
```

- `name`：右栏那一格的字，最长 10 个字符（超过会截断 —— 那一格只有 60 宽）。
- `slot`：`first` / `normal` / `last` 三档，缺省 `normal`。它只决定排在内置入口的前面还是
  后面，不是数字序号 —— 三档够用，也不会出现两个扩展抢同一个位置。
- `icon: true` 表示包里带了一张 `icon.png`（与 `manifest.json` 平级，固定这个名字）。
  不给就画 App 的通用占位标。**只认包里自带的文件，不能填网址** —— 右栏每一屏都要画，
  它不该为一个图标去联网。
- 不写 `entry` 就是「不在右栏占位」：只从别处进来的扩展（比如 Office 那种「打开一份文件」
  才用到的）不需要这一段。
- 这一段坏了不影响安装，只是不占位。卸载之后那一格自动消失，改名字也会跟着变 ——
  入口属于「装了的人」，不用为它发一版 App。

### 3.6 这一页是不是「只属于某一台设备」（可选）

用户可能绑了好几台电脑。有的扩展是「随便哪台都行」（比如一个本地记事本），有的扩展
**整页的内容都来自某一台电脑上的服务**（邮箱、杂志、某个自建面板）——后者进来之前该先问
一句「哪一台」。

在 `manifest.json` 的 `entry` 里加一格：

```json
"entry": { "name": "邮箱", "slot": "normal", "device": "require" }
```

| 写法 | 点右栏那一格之后 |
| --- | --- |
| 不写 / `"any"` | 直接进，用 App 当前连的那台设备。**缺省就是这个。** |
| `"require"` | 先弹「选择设备」，选了哪台，这一页之后只从那一台取数。 |

三条边界，都是刻意的：

- **不声明 = 不问**，所有设备都得能给出这份数据。写歪了（大小写不对、写成布尔）也按
  「不问」处理 —— 最坏的结果是多一次点击，不该让入口点不开。
- **问了之后只认那一台**。页面里 `hostData` 发出的请求由 App 按用户选的那台转发；那台没
  连上就是一条正常的失败响应（`.ok === false`，带 `code`），**照常给用户一句人话**，
  别一直转圈，也别回头去问别的设备要一份数据糊弄过去。
- **一台都没配对 / 只有一台时不会弹**：这种情况下不问也会直接进，别指望「一定有得选」而
  把页面写成「必须等到一个设备 id 才渲染」。

选中的那台会放在上下文里，页面可以读：

```js
window.__DSH_EXTENSION__.device;   // { deviceId: 'office-iMac' } 或 null
```

**只拿它做显示或缓存键**。取数仍然走 `hostData` 那条通道（App 已经按同一台发请求了），
别自己在请求上再挂一个设备参数 —— 那条路没开，挂了也不会生效。

**只有「进去就要数」的整页扩展需要它**。挂在对话里的卡（`content` 那一档）、纯前端的
小工具不需要声明。

## 4. 能做哪些事，怎么申请

能力是一张 App 侧写死的白名单，你只能从里面挑，不能自己发明一项。

| 能力 | 什么时候给 | 能干什么 |
| --- | --- | --- |
| `content.read` | 装完就有 | 读 App 交给这一页的那份内容 |
| `card.write` | 装完就有 | 回写「自己那张卡」的标题与一句说明 |
| `file.pick` | 装完就有 | 弹系统的文件选择器，拿回用户亲手挑的那几份（见 5.6） |
| `file.save` | 装完就有 | 把一份字节交给用户去存（系统对话框里挑落点，见 5.6） |
| `storage` | 装完就有 | 存自己那份数据（App 托管、按扩展隔离、升级不丢、卸载清空，见 5.7） |
| `host.action` | **安装时要用户点同意** | 让宿主替你办一件事（动作名由宿主预先枚举，有的在手机上办、有的在电脑上办） |
| `host.data` | **安装时要用户点同意** | 让宿主替你取电脑上某个服务的接口数据（服务名在包里声明，见第 5.5 节）。**用户选了哪台设备，就由哪台提供**（见 3.6） |
| `net.fetch` | **安装时要用户点同意** | 自己发请求到外面任意地址（见 5.6）。与 `host.data` 的区别只在目标：那条只能打电脑上登记过的服务，这条是外面任何一个地址 |

- 在 `manifest.json` 里写 `"capabilities": ["content.read", "card.write"]`。
- 写了表外的名字不算错，那一项会被当成没写（App 那边可能只是比你老一版）。
- 用户不同意 `host.action` 也照样装得上，只是用到它的按钮点了没反应——你的页面会收到
  一条 `capability-denied` 的回执，别把它当崩溃。
- **动作名由宿主预先枚举**，不是你能现拼的。分两处登记，名字是同一套：
  - **在手机这边办的**：`app/src/services/extensions/actions.ts` 那张表。这里放只能由 App
    做的事（摆一条新对话、预填输入区、跳某一屏）。参数里只该有页面自己掌握的东西；
  - **在电脑上办的**：宿主插件 `lib/mobile/extensions.js` 的登记表。

  查的顺序是先手机、后电脑：手机那张表里有就地办完，没有才转给电脑；电脑也没登记就回
  `extension-action-unknown`。要用哪个动作，先看它是不是已经登记过；没有的话，到对应的
  文件里加一项、并同步这一节，别指望随便填个名字能通。
- **目前登记过的动作只有一个**：`chat.draft`，参数 `{ text: '一段正文' }`。它把这段文本
  摆进一条**新对话的输入区**并切到那条对话 —— **不会替你发送**，用户自己按。正文超过
  8000 字符会被截断。办成回 `{ ok: true, result: { opened: 'new-chat' } }`，正文是空的回
  `action-bad-params`。
- **配对凭据、设备凭据、宿主设置的写、任意文件读写永远拿不到**，这几样不在表里，
  以后也不会加。

## 5. 跟 App 说话

两条通道，形状固定：

**页面 → App**：`window.ReactNativeWebView.postMessage(JSON.stringify({...}))`。认这五种：

```js
{ kind: 'ready' }                                  // 起来了
{ kind: 'close' }                                  // 请 App 退掉这一页（不带顶栏时用它）
{ kind: 'error', message: '画不出来的一句人话' }
{ kind: 'request', id: 'r1', what: 'content' }     // 要这一次的内容
{ kind: 'card', title: '已发布', detail: '刚发出去' }   // 回写自己那张卡
{ kind: 'action', id: 'a1', action: 'publish', params: {} }  // 让宿主办事
```

- 认不出的消息、超过 64KB 的消息**一律被丢掉**，不会报错给你。大内容走 `request` 那条。
- `action` 的动作名只允许字母数字点横线下划线，最长 64。没登记过就回
  `extension-action-unknown`（手机那张表、电脑那张表都没它）；能力没授予回
  `capability-denied`。

**App → 页面**：进来时先注入一段脚本，挂在 `window.__DSH_EXTENSION__` 上：

```js
window.__DSH_EXTENSION__ = {
  protocolVersion: '1',
  slug: 'com.example.thing',
  versionName: '1.0.0',
  capabilities: ['content.read'],   // 实际授予了哪几条
  content: { title: '…', detail: '…' },   // 这一次的内容
};
```

回执走一个事件，不需要知道注入细节：

```js
window.addEventListener('dsh-extension-reply', (event) => {
  const { id, ok, payload } = event.detail;
});
```

## 5.5 取电脑上的数据（`host.data`）

整页应用多半是这个形态：你有一份现成的网页界面，它照常 `fetch('/api/…')`。扩展页从
`file://` 加载，那个 `fetch` 够不到电脑上的服务（跨源、还要凭据）——所以走这条通道。

**声明**：在 `manifest.json` 里加

```json
"capabilities": ["content.read", "card.write", "host.data"],
"hostData": { "service": "magpie", "match": ["/api/"] }
```

`service` 必须是一个**电脑上登记过的服务名**。两类来源：

- 内置的几个（例如 `magpie`）随移动端插件一起走，不归你管；
- **你自己的服务**：在插件自己的 `package.json` 里声明，宿主扫插件时就会登记：

  ```json
  { "dshMobileDataServices": [{ "service": "dsh-email", "allow": ["/api/dsh-email/"] }] }
  ```

  `allow` 是这个服务开放给扩展页的路径前缀，**只认本源的绝对路径**（以 `/` 开头；
  整条 URL、`//host`、相对写法都不认）。这个声明与你的插件同生共死：插件装了才有，
  卸载就没了，不用去改 App 或移动端插件的代码。

  **服务名全局唯一**，撞了以后扫到的优先（按包名排序），所以起名前加个前缀（`dsh-email`
  而不是 `mail`）。内置服务优先于任何第三方声明 —— 你用一个同名声明顶不掉 `magpie`。

`match` 是路径前缀，命中的请求才交给宿主，别的照旧由页面自己发。**两个都要写**：
`manifest` 里的 `hostData.service` 要与 `package.json` 里的 `dshMobileDataServices[].service`
对上，`allow` 要盖住 `match` 里那几条前缀，否则页面发的请求会被宿主按 403 挡回去。

**页面侧不用改一行代码**：App 进来时会装一段拦截，`fetch('/api/state')` 自动转给电脑，
拿回来的东西是一个「够用的 Response」——`.ok` / `.status` / `.text()` / `.json()` /
`.arrayBuffer()` / `.headers.get()` 都能用。也有显式入口：

```js
await window.__dshHostFetch('magpie', '/api/state', { method: 'GET' });
```

几条要知道的：

- **正文可能很大**（几百 KB 是常态），App 按 32KB 分段递回来，你不用管。
- **电脑那边是加密会话，你这边完全不用操心**。App 与电脑之间那层信封（协议 v2）由 App
  在传输层解开再交给你，你的 `fetch` 拿到的就是明文 JSON。**别自己再拼一遍请求、或者
  去读什么密文** —— 那是 App 的事，绕过它只会拿到一堆解不开的东西。
- **失败也是一份响应**：电脑没连上、服务没跑起来、凭据失效，你拿到的是 `.ok === false`
  与一段**带 `code` 的 JSON 正文**（`.status` 可能是 0）。请把它当正常失败处理、给用户
  一句人话；别写成「一直转圈」——那是最难查的一种。
- **`<img src="/api/icons/…">` 这类不走 `fetch`，拦不到**。图标要显示，就让 App 递给你
  （`request` 那条），或者自己带在包里。这是当前的已知限制。
- **没有流式**：SSE / WebSocket 走不了这条通道。要实时刷新就自己轮询。
- **请求体上限 64KB**，超了整条会被丢掉（和页面 → App 的消息同一个上限）。

## 5.6 挑文件、存文件、自己联网

三样都要碰手机本地或外面的网络，所以各占一项能力。前两项装完就有（都得由用户自己动手
才发生），第三项安装时要用户点一次同意。

**挑文件（`file.pick`）**

```js
const files = await window.__dshExtension.pickFiles({ multiple: true, accept: 'image/*' });
// [{ name: 'IMG_0001.jpg', size: 201934, base64: '/9j/4AAQ…' }, …]
```

- 挑哪几份**永远是用户在系统面板里定的**。`multiple` 只是把选择器切成可多选的样式，
  `accept` 只是一个类型提示，改不了「用户自己选」这件事。
- **用户取消回一个空数组**，不是错误 —— 按「他什么都没选」处理就行。
- 单份超过 8 MiB 的会被跳过（字节要过一次 JS 堆，太大的不做）；拿到几份就是几份。
- 拿到的是 base64。要传出去就走 `fetchOut`（见下），别指望 `FormData` 能直接塞。

**存文件（`file.save`）**

```js
const { saved } = await window.__dshExtension.saveFile({
  name: '导出.png', base64: '…', mimeType: 'image/png',
});
```

- 落点**由用户在系统对话框里挑**（iOS 是「存储到文件」，安卓是系统文件存放器）。
  App 不申请存储权限，也永远不会替你决定存在哪 —— 所以这个能力不需要安装时问。
- `saved: true` 是已经写入，`saved: false` 是用户在对话框里取消了，两种都不是异常。
- `name` 只用来给对话框一个默认名：会被切成最后一段（`../a/b.png` 变成 `b.png`）。

**自己联网（`net.fetch`）**

```js
const res = await window.__dshExtension.fetchOut('https://api.example.com/v1/chat', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer …' },
  body: JSON.stringify({ prompt: '…' }),
  contentType: 'application/json',
});
const data = await res.json();   // 与 hostData 那条同形的「够用的 Response」
```

- 回的东西和 5.5 那条**同一个形状**（`.ok` / `.status` / `.text()` / `.json()` / `.headers.get()`），
  两条通道的写法可以共用。
- 只认 `http(s)` 绝对地址。`file://`、`data:`、`javascript:` 都会被丢掉 —— 这条是「上网」，
  不是「读本机」。
- **响应正文按文本回**。要二进制就自己让接口回 base64，或者用别的手段。
- 与 `host.data` 的区别只有目标：那条只能打电脑上登记过的服务（由宿主代取），这条是外面
  任意地址（由手机直接发）。两个都声明了也不冲突，`hostData.match` 命中的仍走那条。

**三样都要做降级判断**：这几个入口只在对应能力被授予时才存在。

```js
if (!window.__dshExtension?.fetchOut) { /* 这一页没有自己联网的权限，按钮别画 */ }
```

写 `undefined is not a function` 的按钮比不画更糟。

## 5.7 存自己的数据（`storage`）

扩展多半要记住点东西：界面偏好、草稿、上一次的筛选条件、一小份缓存。**用这一条，不要用页面
自己的 `localStorage`。**

为什么不让用 `localStorage`：它挂在网页自己的来源上。扩展页是从本地文件加载的，你换一版、
目录一挪，那份数据就可能找不着了；而且它跟别的扩展挤在同一个来源里，键名撞了就是互相覆盖。
这条通道由 App 按你的扩展名落盘，**升级、回退都不动它**，卸载时跟着一起删掉 —— 「卸载」
对用户就该是什么都不留。

```js
const st = window.__dshExtension.storage;

await st.set('settings.theme', JSON.stringify({ mode: 'dark' }));
const raw = await st.get('settings.theme');   // 没有这个键回 null
const theme = raw ? JSON.parse(raw) : null;

await st.keys();                 // ['settings.theme', …]
await st.remove('settings.theme');
await st.clear();                // 清空这个扩展的全部数据
```

几条要知道的：

- **收发都是字符串**。要放对象就自己 `JSON.stringify` —— 每加一层自动序列化就多一处
  「你以为存的是对象、取回来是字符串」的坑。
- **键名有字符集**：字母、数字、点、下划线、横线，最长 128；`settings.theme` 这种命名正合适。
  写歪了回 `store-bad-key`，不会拿去拼路径。
- **单值上限 1 MiB、总量上限 16 MiB**（UTF-8 字节）。**这里不是放大文件的地方**：素材、
  导出物、几 MB 的图该走交付文件那条路。超了回 `store-value-too-large` 或 `store-full`，
  当场就能看出来。
- **写是连体的**：先写临时文件再改名，所以断电最多是「这个键读不出来」，不会变成半截内容。
- **数据跟着扩展走**：更新一版、回退一版都不动它；卸载才清。扩展自己那份 `clear()` 也在。

## 6. 页面自己的约定（外壳契约）

扩展页不是 App 里的一块裸网页：它套在 App 的**外壳**里，与设置、统计、Git 那些页同一套 ——
同一张圆角卡片、同一条顶栏。左边那条是 App 的侧栏，右边那条也是 App 的，**中间这一列归外壳**。

这一节是这个外壳对页面承诺的全部内容。照着做，你的页看起来就是 App 自己的页；不照做，
它就是「一个装在 App 里的网站」，用户一眼能看出来。

### 6.1 外壳替你做了什么

这些**不要自己实现**，做了就是两套：

- **顶栏**：标题、返回键、右侧动作位都是 App 画的。你的页从顶栏下面开始，占满卡片里那块地方。
- **圆角与卡片**：四个角、投影、底色全在外壳那一层。页面自己铺一块满屏底色会把圆角盖成方的。
- **左缘右滑退回**：App 负责，你不用接，也别在页面里抢这条窄带。
- **顶部安全区**：带顶栏时状态栏那一截 App 已经让过了（`--dsh-safe-top` 是 0）；
  自己声明了不带顶栏（`chrome: "bare"`）时，那一段归你让（同一个变量给的是真值）。
- **侧栏**：左边那条是 App 的，横滑开合也归 App。页面里不要再自己做抽屉导航。
  `panel` 档尤其如此：它本来就挂在对话页那张卡里，横滑开合用的就是对话页那条手势。

### 6.2 日 / 夜间配色（`--dsh-theme-*`）

App 有日间和夜间两档，用户随时会切。外壳会把当前那一档**下发**给你的页面，你不用自己维护
第二套主题，也不用读 `prefers-color-scheme`（那是系统外观，不是 App 的档位）。

页面加载前就会注入这几个 CSS 变量，切档时再补注一次（**不重载页面**，你的状态不会丢）：

```css
--dsh-theme-background      /* 整页底色 */
--dsh-theme-surface         /* 卡片 / 面板底 */
--dsh-theme-border          /* 分隔线 / 描边 */
--dsh-theme-text            /* 正文 */
--dsh-theme-text-secondary  /* 次要正文 */
--dsh-theme-text-muted      /* 更弱的说明文字 */
--dsh-theme-primary         /* 主色：重点按钮、选中态、链接 */
--dsh-theme-danger          /* 危险 / 错误 */
```

值都是 `#rrggbb`（**不是** `rgba`），要半透明自己叠，别把 alpha 写死 —— 同一份值在两档底上
都得成立。拿不到时的兜底写在第二个参数上：

```css
body {
  background: var(--dsh-theme-background, #16171b);
  color: var(--dsh-theme-text, #f9fafb);
}
```

另外两样同时在用：

- `<html data-dsh-theme="light|dark">`：要按档位写不同规则时用它，比逐个变量覆盖省事。
- `window.__DSH_EXTENSION__.theme`：脚本里要读当前档位（比如切图表配色）用它，
  形状是上面那八个键加一个 `mode`。

**你自己在 CSS 里定义过的那个变量不会被覆盖** —— 只想改其中一两个、其余跟外壳走，是可以的。

**例外**：「这一页的内容本身就是一张纸」的那种页面（Office 文档预览、图片查看）可以继续用
白底黑字，那是内容的一部分，不是主题。但**页面外壳以内的其余部分**（工具条、空态、报错）
仍然要用上面的变量，否则用户在夜间会看到白纸周围一圈白框。

### 6.3 页面结构

- **内容要自己能滚**：页面高度撑满，别把 `body` 锁死一屏。
- **不要给自己夹内容宽度**：中间那一列宽度由 App 决定（手机上铺满、平板上是中间那栏），
  页面里再写一个 `max-width: 980px` 之类的上限，切页时正文边界会跳。
- **顶部别再让一次安全区**：App 会注入这四个变量，照它们用即可：

  ```css
  --dsh-safe-top     /* 带顶栏时恒为 0px（外层已让过）；chrome: "bare" 时是真值 */
  --dsh-safe-left    /* 横屏挖孔那种，按 env() 的真值 */
  --dsh-safe-right
  --dsh-safe-bottom  /* 手势条 */
  ```

  写法：`padding-top: calc(6px + var(--dsh-safe-top, env(safe-area-inset-top)))`。

  **别用 `viewport-fit=cover` 再自己按 `env(safe-area-inset-top)` 留一段**：在安卓边到边
  底下那个值照样是状态栏的高度，于是顶部会多出一条空白带。要么用上面那四个变量，
  要么干脆什么都别留。
- **有输入框的页面要自己让出键盘高度**：App 那层不替你避让。

### 6.4 顶栏上的东西（要额外位子的话）

默认顶栏只画标题与返回。要往右边放动作（刷新、设置、菜单），需要的话在
`manifest.json` 里说 —— 现在还没开这一档，等第一批有这需求的扩展时再定，别自己在页面顶上
再画一条工具栏（那会变成第二条顶栏，与外壳抢高度）。

## 7. 版本与兼容

- `version` 是**扩展自己的号**，与 App 版本无关。改内容就抬，不抬就是老版本。
- `apiVersion` 是**接口版本**：能力表与消息协议变了才抬。它与 App 的 `RUNTIME_VERSION`
  无关 —— 那个号管的是原生运行时与字节码，跟网页扩展一点关系没有。
- App 抬接口版本时，老 `apiVersion` 的扩展界面上会标出来，不会静默消失；已装的照样能
  打开、能卸载。所以别把 `apiVersion` 当版本号用，它一变就等于重新发一次。
- 扩展的**更新节奏跟着你那个插件发版**：没有独立的扩展热更新。版本号由你在 `manifest.json`
  里抬，抬完插件发一版，用户升了插件、手机上的扩展才会跟着更新（见第 8 节）。

## 8. 发布

现在没有「提交到我们仓库、我们审核」这一步了。你自己发一个 DSH 插件，扩展放在这个插件
包里，用户自己装插件，他的手机就能拉到。

做法：

1. 按正常流程写一个 DSH 插件（`package.json` + 你的代码），扩展目录放在包内任意位置，
   比如 `extensions/<slug>/`，里面是第 2 节那套 `manifest.json` + `index.html` + 包内资源。
2. 在你这个插件的 `package.json` 里加一格声明：

   ```json
   { "dshMobileExtensions": "extensions" }
   ```

   值是这个目录在包内的相对路径（写 `true` 等于默认的 `extensions`）。没有这一格，手机
   就不会去你的包里找扩展 —— 插件里的 `extensions/` 目录名太常见，不声明我们一律不扫。
3. 如果扩展页要读你自己后台的数据，再加一格 `dshMobileDataServices`（见第 5.5 节），并让
   扩展的 `manifest.json` 里 `hostData` 与它对上。只做纯本地的页面可以不加。
4. 把插件发布到你自己的 npm 包或仓库，让用户按正常方式装进他自己的 DSH。装了之后，他那台
   手机连上电脑，扩展页里就会出现你带的扩展。

手机把 slug 拼成「插件名.扩展目录名」（`@scope/name` 里的 `@`、`/` 换成点），这样两个插件
即使有同名目录也不会打架；slug 总长不超过 64 个字符。你那边的目录名照常起就行。

**装得上、打不开是两件事**：下面这些判不过，包根本不会出现在手机上 ——

- 目录里缺 `manifest.json`、或缺入口页 `index.html`（`manifest.json` 里写 `main` 没用，
  手机认死 `index.html`）；
- 整包超 20 MB、文件数超 400、单文件超 8 MB。

这几条是机械判定，不用人审，也不解释原因。其余的（能力声明、页面做什么、会不会往外发
请求）由你自己负责 —— 页面从 `file://` 加载，CSP 挡住外链，包里的资源必须都在包内。

- `manifest.json` 是你写的自述（能力、版本、入口、`hostData`）；逐文件的 `size` 与
  `sha256` 由宿主扫目录现算，不是你填的，别混。
- 官方扩展（Office 预览、magpie）仍随 `dsh-mobile-plugin` 发布、登记在它自己的
  `extensions/catalog.json` 里，和第三方这条是两档；两档来源在 `extension-market.md` 里写清了。
- 作者自己写、自己在手机上边改边看的那条调试路（第 9 节）与发布是两回事：那条走电脑上的
  本地目录，不经过插件包，也不带声明。

## 9. 调试

改一次就发一版太慢。手机这边有一条不走发布的路：**把包放在电脑上，手机上直接装进来。**

这条路的入口是**设置 → 扩展 → 开发者模式**那颗开关，缺省是关的。打开之后，扩展页末尾才会
出现「本地开发」那一段。正式版 App 同样有这颗开关 —— 不用为了调试去要一个开发版安装包。

- 电脑上的目录是 `~/.dsh/extension-dev/<包名>/`，每个装着一个扩展的目录就是一个包，目录名
  就是它的标识。里面照第 2 节的结构放 `manifest.json` 与 `index.html` 那一套，别的文件想
  带就带。
- 手机上打开扩展页，最底下那段「本地开发」点一下刷新，就能看到电脑那边有哪些包。点「导入」
  就装进来；装过的会显示版本，可以「覆盖重装」或删掉。
- 这条链路照样逐文件校验：传一半、被改过一字节，整包都不会落盘（不会留下半个能打开的包）。
- 装进来的包标着「本地」，**不等于发布**：它只在你这台手机上看得见，随插件发版不会带走
  它，别的用户也拉不到。要让别人装上，走第 8 节那条——把它放进你自己插件的包里发一版。

### 9.1 改完几秒就能在手机上看

上面那条路第一次得手动「导入」，之后就**不需要再点任何东西**了：本地包的页面会每 1.5 秒
问一次电脑「我这一份还是最新的吗」，发现内容变了就自己重装、自己重开。判据是文件内容
（哈希），不是修改时间。

电脑这边要配一条命令，让它在你每次保存时把新产物铺到那个目录：

```
node scripts/dev-watch.mjs        # 盯着改，边改边构建 + 同步；Ctrl-C 结束
node scripts/dev-watch.mjs --once # 只跑一次（等同于手动同步一次）
```

它做三件事：构建 → 把产物合成单文件 → 拷进 `~/.dsh/extension-dev/<包名>/`。整个过程两三秒。
**构建失败它不会退出**，只打一行错、等你下一次保存 —— 改到一半的文件是常态。

三个前提与边界：

- 手机那边必须先手动「导入」过一次，自动刷新才接得上（它靠已装记录判断「变了没有」）。
- 只有 `origin` 是「本地开发」的包会这样自动刷；正式来源的包跟着清单更新，不受电脑上那个
  目录影响。
- 自动刷新会重开页面，所以页面里的滚动位置、填了一半的表单会丢。这是有意的：你刚改了代码，
  要看的就是新那份。**别把这条当热更新用** —— 它每变一次就整页重来。

### 9.2 更舒服的一条：页面直接连你本机的 dev server

上面那条每次保存要「构建 → 内联 → 拷贝 → 重装 → 重开」，两三秒一次，页面还会整页重来。
如果你本来就有个 vite / webpack 开发服务器，**可以让手机直接连它**，拿页面自己的热更新 ——
改样式、改组件，手机上当场变，不重开、不丢状态。

做法是往**电脑那份**包目录的 `manifest.json` 里加一格：

```json
"devServer": "http://192.168.1.5:3000"
```

（写进 `~/.dsh/extension-dev/<包名>/manifest.json`，不是仓库里发给别人的那份。）

- **只认私网与回环地址 + http**：`192.168.*` / `10.*` / `172.16–31.*` / `127.0.0.1` /
  `localhost` / `*.local`。写公网地址、https、带路径或查询串，一律当没写。手机与电脑各收窄
  一次，改不动。
- **手机和电脑要在同一个 Wi-Fi**，并且开发服务器得监听所有网卡（`vite --host`）——
  只听 `127.0.0.1` 时手机拨过去指的是它自己。
- **这一格只对本地开发包生效**。正式装进来的扩展永远跑你装的那一份，不会被远程内容顶掉。
- **地址变了当场生效**：手机那侧每一拍都会看一眼这一格，换了地址就换加载源，不用退出去再进。
- **连不上会自动退回本地那份**，不是白屏 —— 但那时你看到的是上一次同步过来的版本。

两条路可以一起用：dev server 开着时走它（热更新）；不想开服务器时就 `dev-watch` 那条
（构建 + 自动重装）。**第一次仍然要手动导入一次** —— 无论哪条路，手机得先知道有这个包。

想看清页面里发生了什么，用本地包顶栏右上角那个调试入口（下一条）。

本地包比正式扩展多一个调试入口（顶栏右上角）。打开后是一条时间线：

- 你在页面里 `console.log/warn/error` 打的东西、没接住的异常；
- 你发给 App 的每一条消息；
- **没被认出来的消息是哪一档原因**：太大、不是 JSON、类型不认识、字段不全；
- App 给你的回执，以及被哪项能力挡了；
- 这一页被注入的上下文：接口版本、版本号、拿到了哪几项能力。

同一条时间线上，消息顺序就是发生顺序，不用在页面上另写日志通道。面板上有「重载」（相当于
关掉再开一次）与「清空」。

正式扩展没有这块面板：它平时不给作者打日志，别在发布版里靠它。

- 页面打不开时，先看 App 给的提示是哪一种：**没装** / **两版都校验不过** / **页面自己
  报了 error**。这三种的出路不一样。
- 能力没授予时的表现是「点了没反应」，但页面会收到 `capability-denied`，打一条日志就能
  分清是能力问题还是页面自己的问题。
- 下载与校验都在 App 那侧，页面里看不到进度；装完再进页面才是新的一版。
