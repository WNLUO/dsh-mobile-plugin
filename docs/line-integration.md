# 把一条线路接进移动端插件

有人做出了一条能拨回这台电脑的入口 —— 自己的反代、内网穿透、服务商给的隧道域名 —— 希望手机
App 把它当成一条可选线路。这份文档说清线路在插件里长什么样、要改哪几处、哪些不用动。

先说结论：**App 和总控都不用改**。插件把线路当数据上报，手机照清单显示和拨号；总控只存密文，
不解析字段。加一条线路的工作量全在插件这一侧。

## 线路长什么样

一条线路只有三样东西：

```js
{ url: 'https://line.example.com', name: '某服务商', transport: 'http' }
{ url: 'line.example.com:9000', name: '某服务商', transport: 'tcp' }
```

- `url`：能拨到**本机插件入口**的地址。http / https 写完整 URL；tcp 写 `主机:端口`（IPv6 用方括号）。
  它要指到这台电脑上 DSH 监听的那个口，不是服务商的控制台，也不是别的服务。
- `name`：只用于显示。手机「选择线路」、连接状态和诊断里看到的就是它，最长 80 字。
- `transport`：`http` 直接按 URL 拨；`tcp` 由手机侧起一条裸 TCP 转发、再拨回环入口。认不出的值一律按
  http 处理。

一条线路只管「怎么走到这台电脑」。走到之后握手、鉴权、会话加密都与别的线路完全一样，不需要也不应该
在线路里另开一条数据通道。

## 要改的地方

### 1. 状态里加一格

线路地址是运行时事实，不是用户设置，所以按现有三条线路的做法：schema 里加一格字符串、默认空串，
`core.js` 的默认状态和 `config-store.js` 的 `configOf` 各补一行。注释写明「运行时写入，手机配置口不
开放」——手机端配置接口不该能改线路，否则等于让远端决定自己连哪儿。

### 2. 拿到地址就写，丢了就清

用 `settings.update({ yourUrl: url })` 写入、写空串撤销。这条链会经 watch → 重配 → `control.sync()`
自动把新清单报给总控，不用自己去找总控连接。

两条现有实现可以照抄：

- 插件自己读本机 API 的（ZeroNews）：`lib/zeronews/watcher.cjs` 定期读、变了才写，读失败时保留旧值。
- 运行时拿到地址的（FRP）：`lib/impl.js` 在 runner 报出地址时写回。

地址形状认不出就当没接（空串），不要留半截地址：一个拨不通的 URL 会让手机多一条永远失败的候选。

### 3. 三处清单各自加上

当前这份清单是分别拼的，三处都要加，形状各不相同：

| 位置 | 形状 | 用途 |
| --- | --- | --- |
| `lib/relay/control.js` 的 `controlAddresses` | `{ kind: 'custom', url, name, transport }` | 加密上报总控，手机换网后靠它拿地址 |
| `lib/routes/mobile-api.js` 的心跳 `customRoutes` | `{ url, name, transport }` | 手机每轮心跳拿到的清单，平时显示与自动档都靠它 |
| `lib/remote/host-control.cjs` | 只取 URL | 电脑连电脑时把这批线路也当候选 |

漏一处的表现很好认：手机平时看得到这条线路，换网或重连后就没了，或者电脑连电脑时少一条。

老版本 App 认的等价条目**只在总控那一处生成**，不要在别处另补，也不要把地址自己写进 `manualLanUrl`
或 `manualTcpUrl` —— 那两格是用户手填的，写了会互相覆盖，而且新 App 会把同址的直连 / TCP 跳过，
只留 custom 那一条。

### 4. 面板（按需）

用户需要在电脑上开 / 关、或者要手填地址时，才动控制面路由和 `React/` 面板。完全自动跟随的线路可以先
不碰面板，只是面板上看不到它的状态。如果这家要在面板里可选、并且出现在首次接入引导页里，按
`docs/provider-onboarding.md` 的清单登记（地区表 / 引导注册表 / 图标文案 / 配置页与路由）。

## 形状和上限

由 `lib/relay/config-store.js` 的 `customRoutesOf` 统一归一，别在调用方各写一套：

- 最多 16 条，超过的部分在配置投影里会被截掉；同一地址只留第一条，上报前还会忽略末尾斜杠。
- `name` 最多 80 字，`url` 最多 300 字。
- 地址里不要带用户名密码、查询串或 `#`。远程电脑会直接丢掉这种候选，手机侧也不会替你剥掉它们。

## 老版本 App 为什么不会掉线

老版本不认识 `custom`，按地址去重、先到先得，未知的 `kind` 会当局域网地址处理 —— 直接用会把它过滤掉，
最后判当前连接失效。所以总控那份清单里，每条线路都会先补一条老 App 认识的等价条目：http 线路补
`direct`，tcp 线路补 `tcp`，排在 `custom` 前面。

于是老 App 看到的是「直连」或「TCP 直连」，没有名字，也不能单独锁定某一条 —— 这是有意的降级，不用去
修。新 App 反过来先认 `custom`，同址的直连 / TCP 跳过。

有一个前提：这类等价条目只走总控。如果用户关掉了地址上报，老 App 就拿不到这些线路（新 App 还有心跳
那条路）。这是老版本自身的边界，不是可以在这层补的洞。

## 别这么做

- **别加新的 `kind`**。新 `kind` 要 App 和插件同时发版才能生效；线路统一用 `custom` + `transport`。
- **别扩移动 API 契约**，也别给手机配置口开这一格。线路是电脑侧的事实，手机只跟随。
- **别为线路另开一条数据通道**。线路只解决「走到这台电脑」，之后的请求仍走同一套 v2 信封。
- **别把 Cloudflare 那种需要自己 `kind` 的兜底隧道当例子**。它是有独立语义的特例，不适用于普通线路。

## 怎么验证

- `test/custom-routes.test.cjs` 钉着上报形状、名字与 `transport` 的透传、老 App 的等价条目；
  `test/remote-custom-routes.test.cjs` 钉着远程电脑那一路。加线路时照这两个文件补一条。
- 三条自检，便宜且能抓到绝大多数错：清单为空时上报内容与加线路之前逐字一致；每条线路都带上了
  名字与 `transport`；撤销（写空串）之后清单里不再出现这条地址。
- 心跳那一格只有一条「源码里确实算了这段」的断言，不验证内容；改完拿 `/api/mobile/v1/status` 实际看一眼。
- 真机验证按项目规矩由人点名，不要自己起设备或模拟器。

## 现成的三条

| 线路 | 地址来源 | 拨法 | 实现 |
| --- | --- | --- | --- |
| ZeroNews | 插件读本机客户端 API | http | `lib/zeronews/` |
| 节点小宝 | 用户从控制台抄一次 | http 或 tcp | `lib/jdxb/` |
| FRP | 本机 frpc 分到的地址 | tcp（反代成域名时是 http） | `lib/frpc/` |

三条都不在手机配置口里，都是运行时写进状态、再按上面的三处发布。新线路照其中最接近的一条抄。
