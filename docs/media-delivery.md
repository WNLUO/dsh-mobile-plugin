# 媒体生成交付（图片 / 视频）

手机端把「图片 / 视频生成」做成**一张固定比例的卡**：生成前占位、生成中更新、结束时原位换成
成品，完成后留在输入区上方供打开 / 保存。图片与视频共用同一条链路，区别只在最终怎么展示。

## 为什么需要插件参与

生成结果不一定是「一条消息里的图片」。它可能是一个**本机回环链接**、生成服务给的**临时地址**、
或一个**已经落盘的文件**。手机拿着 `127.0.0.1` 只会指回手机自己，临时地址会过期，网页内存里的
`blob:` 地址根本下不到。所以**必须由电脑端先把原件收下来**，手机再取这份稳定副本。

## 协议

模型 / 生成插件在生成前调用 `mobile_media`：

| action | 作用 |
|---|---|
| `begin` | 登记任务，给出 `taskId` 与固定 `frameRatio`（比例优先取生成请求参数，未知则图片 1:1、视频 16:9）。必须在一轮运行中调用。 |
| `update` | 更新阶段（`detail`）；**不编造百分比**。 |
| `preview` | 交一张预览图（可选，视频封面 / 生成中间图）。 |
| `deliver` | 交**原件**：本机文件 `path` 或 HTTP(S) 下载地址 `url`（含签名参数）。收存成功即 `ready`。 |
| `retry` | 用上次的来源重收一次（链接失效要先由生成方刷新后重新 `deliver`）。 |
| `fail` / `cancel` | 生成失败 / 取消。 |
| `list` | 当前会话的任务快照。 |

**「交付成功」的定义是：电脑端把原件完整收存到 `$DSH_HOME/storages/mobile-plugin/media`，
并按真实字节识别出的类型与尺寸记账。** 不是「登记了一个地址」。收不到就不算成功，让生成方
补交文件或刷新链接，**不要为了重试交付而重跑一次付费生成**。

收存发生在电脑端、手机不在线也继续；任务与原件引用持久化，插件重启后未完成的任务标成
`interrupted`（明确失败，不重跑生成）。

## 传输与边界

- `GET /api/mobile/v1/media/tasks?sessionId=` 取快照；生成中的变化随会话流以 `media/tasks`
  整帧推送（`revision` 递增，App 只认更新的一份）。
- `POST /api/mobile/v1/media/file` 取**已收存完成**的原件（`{sessionId, taskId, variant?}`），
  走与 `/session/file` 相同的加密分块流；**只认登记过的任务**，不接受任意路径。
- 不新增任何 shell / 系统设置 / 任意文件写能力。

## 桌面端不变

生成走原来的工具与交付；`mobile_media` 只是额外把结果收一份给手机。桌面端继续显示原插件结果
与正常交付，**不改任何可见样式**。AI 主动登记时会留下一次普通工具调用记录；生成插件直接上报
则没有这笔。

## 已知限制

- 失效且无法刷新的链接、`blob:` 内存地址、需要登录且不能导出的预览页面，单凭地址取不回原件；
  必须由生成方导出文件后 `deliver`。
- 视频封面需要生成方给 `preview`；未给时卡片显示占位与播放键，点开用原生播放页（不为了画卡
  把整个视频拉下来）。
- 单份原件上限 512 MiB；手机侧预览另受交付文件那套上限约束。
