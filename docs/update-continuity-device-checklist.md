# 「更新不断」真机验证清单（交给用户执行）

> 目的：确认插件自更新（npm 热更 / OTA 整包）时，各平台、各网络线路下手机侧连接不中断、
> 或短到无感。自动化只覆盖到逻辑与源码；真机行为按项目规矩由用户点名执行。

## 0. 前提
- 桌面宿主：macOS / Windows / Linux 各一台（或按你手上有的来）。
- 手机：Android、iOS 各一台，装最新 App，均已配对。
- 同一局域网可达；如测中转，确保公网中转可用；如测直连，先配好隧道助手 / P2P / FRP。

## 1. 通用观察点（每次更新都记）
- 手机是否有任何「正在恢复连接 / 断线 / 够不着电脑」之类提示闪一下；理想=完全看不到。
- 更新页是否只显示「重连中/重启中」这类普通灰字，不标红、不弹窗。
- 正在跑的对话：流式回复是否续上（允许极短停顿），不出现整段消失或重来。
- 桌面宿主日志里不该出现 worker 反复重启、端口冲突、duplicate route。
- 更新完成后 `/api/relay/status` 与手机「运行状态」里：运行版本=装后的版本，隧道 connected、
  局域网 listening。

## 2. 每条线路单独测（其余线路关掉，只留被测那条）
对 中转 / 局域网直连 / 隧道助手 / 点对点 / FRP 每条：
1. 手机连上、发起一条长回复（确保有持续流）。
2. 手机上点「立即更新」到同一个更高版本（或强制更新）。
3. 记录：长回复是否断续、手机 WS 是否重连、代理状态是否掉过。
4. 更新后再发一条消息、收一条回复，确认新版本正常服务。

## 3. 平台专项
- Windows：更新前隧道助手不再被无故停掉；旧 exe 占用不再导致更新失败；路径含空格正常。
- macOS/Linux：更新期间隧道助手保持运行（不再整段白断）。
- 弱网：在手机上把网络切到较慢（如限速 / 4G），重复第 2 步，确认重连能自己好。
- 前后台：更新时把 App 切后台再回前台，确认自动恢复、不白屏。

## 4. 失败/回滚路径
- 制造一次「装上新版但自检不过」：确认宿主自动退回上一代继续跑，手机侧最多短暂重连；
  重连后「更新结果」如实显示「上次装失败、已退回 X」。
- 制造一次「装包网络中断」：确认旧代继续服务，更新失败如实上报。
