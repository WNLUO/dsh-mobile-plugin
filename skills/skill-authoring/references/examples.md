# 两份样例技能

照这两份的骨架改写自己的技能。样例里的做法是示范，不是唯一写法。

## 样例一：点咖啡

```markdown
---
name: order-coffee
description: 用户要点一杯咖啡外送或自取时用；说「点咖啡」「买杯咖啡」「来杯拿铁」时也用。
---

# 点咖啡

## 入口

从用户指定的咖啡 App（或网页版）开始；不知道用哪家就先问。

## 步骤

1. 打开用户指定的咖啡 App。
2. 搜索用户要的饮品名（如「拿铁」）。
3. 选规格：杯型、冷热、加糖/奶，写成 <杯型> 这类占位，按用户这次说的填。
4. 选门店：外送填地址，自取选离用户近的门店。
5. 核对购物车里的商品名、规格、金额，念给用户确认。
6. 付款前停下（见下），用户确认后再提交。

## 容易出错的地方

- 同名饮品在不同门店价格与规格不一样，先确认门店。
- 加料、糖度常藏在「规格」二级页，别漏。
- 外送会有起送价与配送费，金额核对时要一起念。

## 怎样算办成

- 用户看到订单已提交，且商品、门店、金额与确认时一致。
- 把订单号或截图交给用户。

## 什么时候停下交给用户

- 付款：必须由用户在手机侧确认，AI 不自行付款。
- 需要选择时的模糊点（换门店、改规格、地址不确定）先问。
```

## 样例二：导出周报

```markdown
---
name: weekly-report
description: 用户要把本周做的事整理成一份周报（Markdown 或文档）时用；说「写周报」「总结这周」时也用。
---

# 导出周报

## 入口

先确认周报的时间范围、给谁看、要什么格式（Markdown / Word / PDF）。

## 步骤

1. 确认范围：本周起止日期、目标读者。
2. 收集素材：本周的会话记录、提交、完成的任务。
3. 按「完成 / 进行中 / 下周计划 / 风险」四段组织。
4. 每条写清做了什么、结果如何，能带数字就带数字。
5. 按用户要的格式落文件，交给用户。

## 容易出错的地方

- 别把过程流水账全抄进去，只留结论和结果。
- 日期范围算错会导致漏事，先跟用户确认。
- 引用数字要和素材对得上，对不上就别写。

## 怎样算办成

- 产出文件，四段齐全，内容与本周素材一致。
- 用户能在交付里打开这份文件。

## 什么时候停下交给用户

- 时间范围或读者不明确——先问。
- 素材涉及他人隐私或敏感信息——不写，告诉用户。
```
