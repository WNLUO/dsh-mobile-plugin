# 自建中转程序（Rust 中转 dsh-relay）

手机和电脑隔着公网时，中转是它们的落脚点：转发 HTTP、SSE 和 WebSocket，电脑上的插件主动建一条出站 WSS 隧道上来。好处是家里不用公网 IP、不用在路由器开端口。自己架一台就是这个二进制，纯转发、一个服务；可选再开中转控制台管谁能建隧道。这里讲怎么架、怎么让电脑和手机用它。

## 先认清自己站哪边

- 跑在用户电脑上、有本机 shell —— 执行者：自己查中转地址、自己 curl 中转体检口、自己核对配置。
- 回反馈、够不着用户那台电脑 —— 指导者：一步一步说给用户做，请他回报结果，不谎称自己登过服务器。

## 开查前先问一句（话要短）

「中转架在哪、域名是什么、电脑这边填的中转地址是哪个？」能直接答就往下走；不清楚再要，别上来一大段。

## 部署这台中转

- 常规用**一键装**：在一台有 systemd 的 Linux 上用 root 跑官方安装脚本。它下载编好的静态包（x86_64 / aarch64 都有），先核 sha256、再 `--version` 确认这台机器起得来，然后装到 `/opt/dsh-relay/`、写 systemd 单元、启动并打开自动更新。不用装 Rust、不用编译。
- 脚本**刻意不碰**三样：不改你的 nginx、不配 TLS、不开控制台——证书方式太多，猜一种会把机器配歪。它跑完会打印一段 nginx 反代片段，把域名指到本机监听端口（默认 `127.0.0.1:18788`）就行。
- 生产必须给一个带 TLS 证书的域名，前面挂 nginx/Caddy 终结 TLS；App 走公网只接受 HTTPS/WSS，裸 http 的中转地址用不了。
- 只有要改代码才走源码编译那条（cargo build --release），普通部署不要走——编一次要装两百多兆依赖。
- 纯转发默认一个环境变量都不用配。可选能力按需开：控制台用 `PLATFORM_ENABLED=1`，注册密钥 `TUNNEL_REGISTER_SECRET`（设了则每台宿主插件要配同一个值，防止别人顶掉隧道），这些按部署文档来，别默认全开。

## 让电脑和手机走这台中转

- 中转地址是一组：`relayUrls` 是完整列表、`relayUrl` 恒为它的首项（主用那条）。在电脑插件的面板里把自建地址填进「自建中转」那一栏。公用中转已下线，不用再管它；遇到旧地址直接引导改走这台自建中转。
- 集齐这些再上手机：中转域名、配对码、设备。换网或重启后地址不变就稳了。
- **注册密钥**如果中转那侧设了，电脑插件这侧也要填同一个值（桌面设置里的「注册密钥」，无头部署用环境变量），否则隧道注册时被拒。

## 上手机前验收

按 `references/selfhost-common.md` 的四条思路，但中转有自己的体检口：

1. `curl https://你的中转域名/healthz` 回 2xx，且 `curl https://你的中转域名/api/mobile/v1/health` 回的 `service` 是 `dsh-mobile-relay`——两个都对才算这台确实是中转（只看 `/healthz`，任何静态站都会回 200）。
2. 面板的中转测速（`probe-relays`）能测出真实延迟，不是超时或 null。
3. 手机断 Wi-Fi 走流量，能连上电脑、聊天一段段出、内置浏览器能开。
4. 大文件上传走一遍，没被截断。

## 几个坑

- **只监听回环**：一键装默认绑 `127.0.0.1:18788`，必须前面有反代；直接把公网域名指过去而不挂反代，或不小心用默认 `0.0.0.0` 裸跑，等于把明文 HTTP 和凭据暴露在公网。
- **来源 IP 只在回环才信**：`/status`、来源诊断只认本机来源；反代放在另一台机器或独立容器（Docker 常见）时，中转看到的是容器网桥地址，这些接口会失效。让反代和源站同机同网络命名空间，别默认它能用。
- **公网 IPv6 不一定有**：App 也可能走 IPv6 直连，手机蜂窝那侧得支持 IPv6，否则那条路不成立；但走中转这条路不依赖公网 IP。
- 中转只是转发，不判断谁能进哪台电脑；准入控制（谁能建隧道）是可选控制台的事，配对码和设备凭据仍是电脑这侧说了算。

## 什么时候停

- 体检口对、测速通、手机流量实测过，才算这台中转可用；少一样就说清卡在哪一步。
- 服务器部署、TLS 证书、控制台配置因机器和域名而异，查不到就让用户按部署文档来，不硬编命令或密钥。
- 令牌、注册密钥、控制台密钥只在当次用，用完不留存、不写进记录、不在回复里复述。
