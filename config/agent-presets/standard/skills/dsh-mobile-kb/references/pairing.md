# 配对失败（stage 分档）

扫码之后分三段：解析二维码 → 检查明文限制 → 拿码去换凭据。任何一段抛错都落在同一行，但 `stage` 不一样，处理办法也不同。反馈里出现的 `stage: auth` 指的是换凭据那一段，不是解析。

## 怎么读 stage

- `parse`：先分清两种。一是二维码本身解析失败（码坏了、不是这张码、截断）——重新对准、重扫，重复失败要原码。二是**码解析出来了、但里面一条可用地址都没有**，报「二维码没有可用的连接地址」——这不是码坏，是电脑那侧没配好可连的地址（没配中转、局域网没起来、隧道没连）。引导去电脑插件页把中转或局域网配好、确认隧道连上后**重新生成一张二维码**再扫，而不是对着同一张码反复重扫；仍不行再要码截图核对。
- `cleartext`：只在直连局域网、且是 iOS 时出现——明文 HTTP 被系统 ATS 拦掉。不是凭据问题，换用中转或 https 入口。
- `auth`：拿邀请码去换凭据时失败。先按报错文案分三种，处理不一样：
  - **电脑掉线 / 中转断了**：最常见。人在电脑上弄好之后，用同一张码点「再试一次」即可，不用爬回上一页重扫。
  - **配对码不对 / 电脑拒绝了新设备**：这不是掉线，是这张码没被认可。别让用户对着同一张码反复点重试——引导在电脑上**重新生成一张二维码**、用新码尽快扫（码放久会失效）；反复出现再查电脑端的设备授权。宿主刻意不区分「码错」和「策略拒绝」，所以两者是同一句提示。
  - **「局域网地址和中转地址都拨不通」/「当前连接验证失败」**：地址探测层面两条路都没通。先确认电脑 DSH 开着、中转显示已连接；手机在外面（和电脑不同网）时局域网那条本就不通，要配好中转或改走能到的线路。确认后用同一张码点「再试一次」；仍不通按中转侧取证，别反复重装。
- `credential`：凭据写进系统凭据库失败。界面会给「清空本机配对记录重扫」的入口；按它走，不要让用户手动翻系统设置。
- `save`：第四页点「开始使用」时的验证失败——这一步会真打一发确认电脑认这枚凭据、路通不通，不通就停在这一页，不会把人放进主界面再报「读取失败」。
- `reset`：清本机配对记录那一步失败，照报错原文处理。

## 第一次配对，二维码/配对信息从哪来

用户问「怎么拿到配对信息」「二维码在哪」「怎么开始配对」这类，还没到失败排查，按首次引导答：在电脑上打开 DSH，进到移动端插件页面，那里能生成二维码（或配对码）；手机 App 里点「添加设备」扫这张码，或手输配对码，就能配上。找不到入口时再问一句电脑 DSH 什么版本、现在停在哪个页面，指给他看；不要一上来就当故障排查。

## 判断是不是同一 WiFi

`auth` 这一类，App 会按二维码形状分档：

- 码里只有局域网地址 → 告诉用户三种可能：不在同一 Wi-Fi、电脑插件没开、电脑防火墙拦了。
- 码里带中转地址 → 走公网那条路，重点查中转是否在线，`同一 WiFi` 那三种不适用。

## 给用户的信息清单

版本与系统（含构建号）、配对方式（扫码还是手填、局域网还是中转）、报错原文和 `stage`、是否点了「再试一次」、电脑上插件面板显示什么。缺这些就说缺，不要先下结论。

## 边界

配对码是一次性的邀请，别在回复里复述完整码、凭据或二维码内容。反复在 `auth` 失败且电脑在线的，属于待定位，不写成「已修复」。
