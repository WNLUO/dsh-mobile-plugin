# 直连地址被加了端口（填了域名，却变成 `:18787` / `:51887`）

用户说在面板「直连地址」那格填了 `http://域名` 或纯域名，回读时末尾却多出 `:18787`（老默认值）或 `:51887`（新装默认值），点「检测」回环还连不上，于是怀疑面板偷偷补端口。先分清这端口是谁加的——面板保存和总控同步都不加，最常见来源是**老版本手机 App 保存连接地址时做的规范化**。

## 先认清症状

- 直连那格显示的地址带一个用户没填过的端口，通常是 `:18787`（老默认）或 `:51887`（新装默认）。
- 回环检测落在「连不上，请检查地址、端口或反代路径」；配了反代路径的域名被截成 `http://域名:18787` 时尤其明显——原本该拨的端口/路径不是这个。
- 用户常坚持「我是在面板里填的」。这不矛盾：面板只存他当时填的字，显示的是宿主已经存下的那份；端口多半是更早一次从手机那侧写回来的。

## 端口是谁加的（按这三层分）

- **手机 App 老版本的地址保存（最常见来源）**：老包网络页有一张可编辑的「连接地址」卡，保存时会把地址过一遍规范化——没写端口的明文 http 地址会按默认端口补上（老版本 `18787`），再回写给宿主。面板这次读到的就是补完的那条。新版本 App 已撤掉那张可编辑卡，地址只在电脑面板改，不再回写。
- **电脑面板**：保存只去首尾空格和结尾斜杠，不加端口。界面里看到的带端口值，是回读宿主已存的 `manualLanUrl`，不是这次保存加上去的。
- **总控**：总控只搬运地址串，快照下发到手机会话也是原样；面板「立即同步」是只读比对，不回写宿主配置。它不会往地址里添端口。

## 怎么查、怎么回

1. 先问清：这地址**最早**是在哪填的（电脑面板还是手机 App 网络页）、当时填的原文是什么、有没有反代路径。一次问一两个就够了。
2. 收版本：App 版本、电脑插件版本、DSH 版本。老版本 App 才走那条补端口的保存路径；新版已经不回写，别把旧现象当成现在还在发生。
3. 让用户在面板把那格清空，按真正要拨的地址重填——带反代路径要写全 `http(s)://域名/路径`，该带端口就明写端口——保存后再点「检测」看回环是否命中本机。
4. 端到端终判交给手机：断 Wi-Fi 走流量实测能不能连回这台电脑；电脑侧自检只作自查，不作证据。

## 边界

- 这是排查知识，不是修复记录：新版 App 不再回写这类地址，但老包仍在外面，遇到就按上面识别、改回，别写「已修复」。
- 排查侧不替用户改配置、不重启服务、不动产品代码；改地址、升级 App 由用户自己做。
- 回答里说清现象、版本与环境、确认到哪一步、依据、下一步；确认不了的标「待补充」。
- 地址里的令牌、密钥不写进知识库，也不在回复里复述。
