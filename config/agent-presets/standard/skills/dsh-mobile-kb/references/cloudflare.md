# Cloudflare 快隧道兜底

没有服务器、没有域名时，可以用 Cloudflare 快隧道把电脑上的服务端口搬到公网，手机拨 `https://xxx.trycloudflare.com`。它和 frp 站同一格，顶替的是中转，不是新功能——鉴权和配对还在电脑这侧，Cloudflare 只看到元数据。**这是插件内置的开关，和 tailcat、P2P 一样默认关闭，不是让用户自己装 cloudflared、也不是去 Cloudflare 后台建隧道。** 共用的栏位和验收见 `references/selfhost-common.md`。

## 先认清自己站哪边

- 跑在用户电脑上、有本机 shell —— 执行者：自己看面板状态、自己 curl 公网地址验体检口和鉴权。
- 回反馈、够不着用户那台电脑 —— 指导者：一步一步说给用户做，请他回报结果，不谎称自己起过隧道。

## 开查前先问一句（话要短）

「面板里那行 Cloudflare 兜底隧道开关打开了吗？状态行显示什么？」能直接答就往下走；不清楚再让他截图或念状态，别上来一大段。

## 这不是「你去装个 cloudflared」

先把这点纠正过来，少走弯路：**开关在网关面板的网络设置里，打开就有**。插件会自己准备 `cloudflared` 二进制、自己起隧道、自己把地址写进直连格。用户不需要去下载 cloudflared，也不需要注册 Cloudflare、绑域名、建命名隧道——那是这条快隧道刻意避开的。看到有人正要手动装，先拦下来，让他回面板点开关。

## 面板怎么开、看什么

- 网络设置里「Cloudflare 兜底隧道」这行：打开即起一条临时隧道，关掉即停。
- 同一行四个状态：**可用 / 运行中 / 当前地址 / 错误**。当前地址形如 `https://随机词.trycloudflare.com`，以状态里显示的那条为准。
- 面板读的是 `/api/relay/status` 里的 `cloudflare` 那格；起不来时先看这格的错误，再往下查。
- 地址会写进「直连地址」那一格（不是 TCP 栏，那是 frp 的），总控上报、配对二维码、面板回显都会自动带上；开启前你手填的直连地址会存一份，关掉自动还原。

## 地址每次重启都会变

快隧道的 `*.trycloudflare.com` 不是固定域名，隧道一重启就换一个。手机能拿到新地址，靠的是「总控」：插件把新地址写进直连格后自动上报总控，手机下次问总控就是最新的。所以：

- 别让用户把这个地址当固定域名记下来、贴到别处去用。
- 总控上报关掉或用不了时，这条兜底就拿不到新地址——先把总控恢复，地址才会跟着变。
- 同时手填了直连地址的话，两者不并存（开启会占这一格）。

## 上手机前验收

按 `references/selfhost-common.md` 四条过一遍：体检口 `curl https://xxx.trycloudflare.com/api/mobile/v1/health` 回带 service 和版本的 JSON；不带 token 访问 `/status` 回 401 JSON；手机断 Wi-Fi 走流量实测 SSE 流式（聊天能否一段段出来）和 WebSocket（内置浏览器能否打开）；传个稍大文件看有没有被 100MB 上限截断。WSS/SSE 是能穿的，流式卡住先查应用层心跳和总控，而不是先怀疑地址。

## 已知限制

- 快隧道是 Cloudflare 标「测试用」的：有并发和创建频率限制，没有可用性承诺。少量自用兜底够用，别当 SLA；要长期稳定得回到「有域名 + 一次性授权」的命名隧道。
- 免费版单请求体上限 100MB，大文件上传会被截断；WSS 分片与 SSE 可穿。
- tunnel 本身不鉴权：谁拿到 URL 谁能摸到那个端口，挡在前面的是插件令牌 + 配对。两个免鉴权体检口在公网可被扫到，量级同 frp 这类公网入口。
- 开启期间占用「直连地址」那一格，关闭恢复原值。

## 几个坑

- 别把地址当固定域名：每次重启会变，靠总控兜平，重启后拿不到新地址先查总控上报。
- 大文件会被 100MB 上限截断，要传大的就别走这条。
- 频繁开关可能撞上创建频率限制，起不来先等一会儿再点，别反复狂点。
- 地址别到处贴：拿到 URL 的人能试着连端口，安全靠插件令牌 + 配对，想更保险就定期轮换配对码。
- 起不来先看状态行的错误：是不是二进制没下来 / 平台不支持 / 端口还没就绪；`cloudflared` 是从网络拉的，第一次会慢一点，拉不下来就等网络好了重试。
- 国内不少网络根本连不上 Cloudflare：状态行会显示「连不上 Cloudflare（可能被屏蔽或被代理拦截）」，这是网络问题不是插件坏了，别反复重开，改用中转 / 局域网直连等其它入口；插件不会因此报错或闪退，任何失败都会在状态行给出原因。
- 面板只报状态，终判认手机断 Wi-Fi 走流量实测，别拿电脑侧 curl 通当「手机一定能用」。

## 什么时候停

- 没网、又拉不下来 `cloudflared`：如实说这条暂时起不来，可走 IPv6 直连、frp 或中转，不写「已修复」。
- 隧道起了但实测不通、查不出原因：把卡在哪一步（状态行 / 体检口 / 鉴权 / 流式 / 100MB）说清，标「待定位」，别假装查完。
- 需要长期稳定、大文件、多设备：如实说快隧道不适合，建议换命名隧道或自建入口，不硬撑。
