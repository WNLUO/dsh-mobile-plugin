# 自建公网入口：共用的几件事

这一篇是 IPv4 公网、IPv6、frp 这些「自己把电脑搬到公网」方案的共用部分。选定哪种方案后，都来这里对一遍栏位、域名、反代和验收，别每种方案各写一套。

## 三栏各填什么（填错栏就走不通）

App 里有三个不同的地址栏，别混：

- **直连地址**：`http(s)://主机` 或 `http(s)://域名:端口`。IP 或域名都收，http 和 https 都收。有域名、有 DDNS、有反代，通常填这里。
- **IPv6 直连**：宿主上报或手动填的 IPv6 地址，形如 `http://[240e:...]:端口`。只有"这台电脑自己的公网 IPv6"才填这里；给它绑了域名就别填这栏，去填直连地址。
- **TCP 直连**：`主机:端口` 的裸 TCP 目标（IPv6 用方括号），App 走本机回环转发。frp 的 tcp 隧道这类填这里。

一个地址只填一次：同一条路别既填直连地址又填 IPv6 栏。旧宿主会把直连地址并进局域网列表，新手机读到会剔掉；换宿主时以这台电脑上报的为准。

## 有域名就上 DDNS（v4、v6 都适用）

家里宽带基本是动态 IP，域名要跟着 IP 变才有用。

- 工具随便挑，ddns-go 这类都行：在能拿到公网地址的那台机器（电脑本身、或 NAS）上跑，配好域名和 DNS 服务商的密钥，它定时把当前公网 IP 写进解析。
- IPv4 公网就更新 A 记录；IPv6 公网就更新 AAAA 记录；两个都有就各绑各的，或绑同一个域名让系统自己选。
- 前缀会变（IPv6 尤其常见）：光猫重启、运营商重下发，地址就换一轮。DDNS 负责追这个变化，别手动改。
- 域名解析生效后再上手机：`dig A 域名` / `dig AAAA 域名` 看是不是当前公网地址；还没生效就等着，别急着填。

## 前面挂 Nginx / 网关反代（NAS、家庭服务器常见）

DSH 部署在 NAS 或家庭服务器上、前面已有 Nginx/Caddy 时，可以把 TLS 终结在网关、域名指向网关，由网关把请求转到电脑上那个服务端口（默认 `51887`）。

两个必须处理的点：

- **SSE 和 WebSocket 要能穿**：聊天要一段段出、内置浏览器要能开。反代若开了响应缓冲就会变成"整段才出来"或卡住。把对应路径的缓冲关掉、升級头按 WebSocket 透传。上手机前用配对好的设备实测流式，这是决定好用不好用的关键。
- **源站只认回环过来的真实 IP**：中转和插件面板对 `/status`、来源诊断这类接口，只在连接来自本机回环时才采信真实 IP 头。反代若在同一台机器的另一个容器里（Docker 常见），对源站来说不是回环，这些接口会拿不到真实来源。要么让反代和源站同网络命名空间、要么按部署文档把来源头的事配好，别默认它一定能用。

## 上手机前的验收（每种方案都过一遍）

1. **地址通不通**：电脑上 `curl https://域名/api/mobile/v1/health`（或 `http://IP:端口/...`），应回带 `service` 和版本的 JSON。这是体检口，不带 token 也能回。
2. **鉴权有没有生效**：不带 token 访问别的路径（如 `.../api/mobile/v1/status`），应回 401 JSON。若直接回数据，说明暴露面不对，先别用。
3. **流式能不能穿**：SSE 长连接和 WebSocket 用配对好的手机实测——聊天能否一段段出来、内置浏览器能否打开。被缓冲就回去调反代或换隧道类型。
4. **大文件上传**：传个稍大的文件走一遍，确认没被截断。

## 什么时候停

- 体检口通、鉴权对、流式和大文件都过，才算这套部署可用；少一样就把卡在哪说清。
- 反代和 DDNS 的具体配置因 NAS 型号、DNS 服务商而异，查不到就让用户按型号/服务商找文档，不要硬编配置或密钥。
- 密码、DNS 密钥、令牌只在当次用，用完不留存、不写进记录、不在回复里复述。
