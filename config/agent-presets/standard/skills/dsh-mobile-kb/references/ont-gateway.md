# 进不去光猫后台、忘了后台密码（找回自有光猫的管理凭据）

IPv6 直连要进光猫关防火墙、端口映射要进光猫做映射，都卡在同一件事：用户手上没有能登录后台的管理员密码。运营商定制光猫的密码常被 TR-069 定期轮换，贴纸上的普通账号进不去。这一篇讲怎么在**用户自己的设备**上把当下有效的后台密码找回来。拿到密码、改完开关之后怎么验收，回到 `references/ipv6.md` 或 `references/ipv4.md`。

## 先认清自己站哪边

- 跑在用户电脑上、有本机 shell，且那个光猫凭据自查工具（`WNLUO/ung220z-tool`）在这台电脑上 —— 执行者：自己识别固件家族、自己跑工具、自己回读确认。
- 回反馈、够不着用户局域网，或电脑上没这个工具 —— 指导者：一步一步说给用户做，请他回报结果，不谎称自己登过后台、跑过工具。

## 开查前先问一句（话要短）

「这台光猫是你自己的吗？背面贴纸还在吗？」自有设备才往下走；贴纸上有账号密码先看贴纸。别上来一大段。

## 先确认能碰

只针对用户**自有设备**的自查与维护：找回自己忘记的密码、迁移自己的宽带配置。用户说不清设备归属、或是别人的光猫、公司/房东的网关 —— 停，不提供提取方法，转「什么时候停」。这是前提，不是走过场的免责声明。

## 按顺序查，别跳

1. **先看贴纸。** 光猫背面 S/N 标签常有「用户名 user / 密码 xxxxxxxx」，先用它试普通后台。运营商定制机常把 Web 普通账号和超级管理员分开，贴纸那组只能进普通页；能进普通页也有用 —— 从页面读固件信息、判断家族。
2. **判断固件家族，别一台台硬试。** 用户电脑上有工具时，先跑家族识别：`python3 -m ontkit probe -H <光猫IP>`，工具会打印设备指纹（`Server` 头、页面标题）帮助判断。也可用浏览器看有没有 `telnet.gch` 这个接口：返回 404 基本就不是九联/吉比特那套 `.gch` 固件，别再按 `.gch` 的路子试。
3. **按家族走对应入口**（都在那个仓库里：`python3 ung220z.py` 是九联 UNG220Z 主脚本，`ontkit` 是多厂商适配）：
   - 九联 / 吉比特 `.gch`（UNG220Z 等）：主脚本开 Telnet → 读配置库 → 提凭据。
   - 中兴系（G7615 / UNG853H / 吉比特 H3-2，部分默认端口 8080）：走 `webFac` 工厂模式。
   - 烽火 HG6042A1：用设备 MAC 走 `telnetenable.cgi` 开 Telnet，再读 `show admin_pwd`。
   - 华为 ssmp（HS8145X6 / B866-L1）：实验性，只做 Web 登录并尝试开 Telnet，不保证成功。
4. **提不出来的先收日志。** 只有 UNG220Z 是作者真机验证，其余型号来自公开案例或未验证。工具打印的指纹那一行（`Server=... title=... 特征=...`）和退出码是定位关键，照着收，别把未验证型号的案例当通用做法。
5. **拿到密码后回到原问题。** 进后台关 IPv6 防火墙 / 做端口映射，改完回读确认（见 `references/ipv6.md` 第 4 步）。后台密码只在这次用，用完不留存、不写进任何记录、不在回复里复述。

## 几个坑

- Web 登录和 Telnet 是**两套账号库**：Web 密码进不去 Telnet 是常事，工具会依次尝试贴纸账号、超级管理账号、从 Web 页读到的 Telnet 项；用户若知道两者口令不同就提前说。
- 口令里含 `%` 一类字符时，拼进 URL 会被当成转义、服务器返回 400；工具已处理，手工拼 URL 时别忘了编码。
- 连续登录失败（通常 3 次）会让设备进入延时校验：**立即停止重试**，静默等 10～30 分钟再说。别一遍遍试把设备锁死。
- 运营商定制机常关掉或锁住工厂模式 / 高级入口，工具会报「不可用」；这不是没找到密码，是这条路走不通。
- 国内家宽（移动定制的九联、吉比特、中兴为主）和海外差异大：海外运营商租借网关（Comcast、BT、DT 等）常把管理员权限锁死，用户手里只有普通账号，找回密码也改不了防火墙 —— 直接转「什么时候停」。国内也有类似的锁死网关，别把某一台设备的入口当成通用账号密码或通用入口。
- 光猫重启、TR-069 远程下发之后密码可能又轮换，之前拿到的会失效。

## 什么时候停

- 不是用户自有设备、或归属说不清：停，不提供提取方法。
- 运营商锁死网关、没有管理员权限：如实说这台改不动，转中转或两条内置隧道（直连隧道、点对点隧道）；不写「已修复」。
- 多次失败进了延时校验：停，等 10～30 分钟再试；还不行就请用户提供指纹行和退出码，标「待定位」。
- 未验证型号按公开案例试了仍拿不到：把卡在哪一步说清，收日志再迭代，不编结论。
