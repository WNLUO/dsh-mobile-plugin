# 电脑端插件未装载 / apiProxy 未注入

连接是通的，但手机一读会话列表、工作区、消息就失败，报错里带 `cannot get property "apiProxy" without inject`。这一篇讲怎么认、怎么处理，别当成手机网络问题甩给用户换网。

## 先认清症状

- 报错文案：「加载会话/工作区失败：电脑服务处理失败：cannot get property "apiProxy" without inject」，或「这台电脑没有注册 session/list：对应的宿主插件没加载」。
- 携带的诊断里，短时间内大量 `apiProxy` 未注入（`session/messages` 常是 HTTP 502、`sessions`/`workspaces` 常是 500），而手机侧延迟正常、`outages=0` —— 据此判定问题在电脑端移动端插件这一侧（没装载，或装了但版本旧、兼容桥没提供），不是手机网络、也不是配对码、更不是"重新扫一次码"能解决。
- 另一类同族：网关在、但服务没注册，报 400 `host-unavailable`（这台电脑没有注册 session/list）、503 `tunnel-unavailable`（隧道给不出地址）；可能与"电脑离线"提示一起出现。

## 稳定处理口径

1. 先确认电脑上的 DSH 在运行、插件页里「DeepSeek Harness 移动端」是启用状态。
2. 完全退出电脑上的 DSH 再重新打开，让插件重新装载，等它重连。
3. 回 App 重试；归档会话和镜像在电脑上，重连后会回来，不是数据丢了，别让用户以为聊天记录没了。
4. 仍复现：收电脑侧版本号（DSH 版本 + 移动端插件版本，插件页可见），按"某版本普遍装载失败"交给维护者核查，**不要反复让用户重启或换网**。

## 边界

- 这是排查知识，不是修复记录。启动宽限期那类 `apiProxy` 未注入，插件在较新版本（≥0.5.91）已改成"启动即提供兼容桥"，能消除这一档；但这不等于所有设备复现都算解决——持续复现仍要按电脑侧版本证据核查，别写"已修复"。
- 排查侧不替用户改配置、不重启用户服务、不装卸载插件；重启由用户自己做。
- 手机侧延迟正常时不要把锅甩给网络；同理也别凭一句报错就断定某版本一定有 bug，要版本证据。
