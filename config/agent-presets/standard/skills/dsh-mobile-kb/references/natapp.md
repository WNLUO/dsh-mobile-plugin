# natapp 内网穿透（不养中转服务器）

不想自己架中转服务器时，可以用 natapp 这类内网穿透把电脑上的服务端口映射成一个公网 https 域名，手机把它当**直连地址**用。它顶替的是中转，不是新功能——鉴权和配对还在电脑这侧，安全模型跟走中转一样。共用的栏位、DDNS、反代、验收见 `references/selfhost-common.md`。

## 先认清自己站哪边

- 跑在用户电脑上、有本机 shell —— 执行者：自己查客户端状态、自己 curl 域名验体检口和鉴权。
- 回反馈、够不着用户那台电脑 —— 指导者：一步一步说给用户做，请他回报结果，不谎称自己起过客户端。

## 开查前先问一句（话要短）

「natapp 客户端跑起来了吗？域名是免费的还是固定的？」能直接答就往下走；不清楚再要相关信息，别上来一大段。

## 按顺序查，别跳

1. **隧道是不是固定域名。** 免费隧道的域名每三天强制换、还不定时变，一换配对就断，只适合临时看一眼。日常用要最低那档付费拿固定二级域名。用免费域名又反复断线的，先换固定域名，别在别的方向上找原因。
2. **客户端在不在跑。** natapp 提供 Windows / macOS / Linux（含 ARM）的二进制。带参数跑 `./natapp -authtoken=...`，或在同目录放 `config.ini` 写 `authtoken`。看到 `Forwarding https://xxx.natapp.cc -> 127.0.0.1:18787` 才算通。本地端口是插件服务监听的端口，默认 `18787`，改过就以状态里报的实绑端口为准。**客户端要一直开着，关了隧道就断**——这是掉线最常见的原因，先确认它没退。
3. **填哪个栏。** 手机把它当直连地址用：已配对的设备进「网络」页，在「直连地址」栏填 `https://xxx.natapp.cc`，通道偏好选「直连」或「自动」。第一次配对要先在电脑本机设置里把同一个域名填成手填直连地址，这样配对二维码会带上它、手机扫码直接用这条域名配对，全程不碰中转。别填进 IPv6 栏或 TCP 直连栏。不用中转就把中转开关关掉，只留这条直连也能工作。
4. **上手机前验收。** 按 `references/selfhost-common.md` 四条过一遍：体检口 `curl https://xxx.natapp.cc/api/mobile/v1/health` 回带 service 和版本的 JSON；不带 token 访问 `/status` 回 401；手机流量下实测 SSE 流式和大文件上传。流式那条最关键——有些穿透工具会缓冲响应，表现是「整段才出来」或「卡住不动」，撞上就换 natapp 的隧道类型或换一家。

## 几个坑

- **免费域名会轮换**：三天一换、不定时变，每次都得分手重配；别拿它当长期方案。
- **一条隧道只连一台机器**：natapp 一个隧道对应一个本地端口，多台电脑各开各的。
- **客户端关了就断**：排查掉线先确认 natapp 进程还在、没被系统休眠或关掉。
- **安全**：域名别到处贴，别人拿到能试着配对，好在配对码有限流、控制面被挡；想更保险就关掉中转只留直连，并定期轮换配对码。
- **它不是端到端加密**：和 frp、自建中转一样，natapp 那侧能看到明文流量；请求正文另有应用层加密，裸的是元数据和凭据这一层。
- 电脑侧面板只报「设备数 / 最后在线」，终判认手机断 Wi-Fi 走流量实测。

## 什么时候停

- 客户端起了、域名固定、验收四条都过，才算这条路可用；少一样就把卡在哪说清。
- 流式被缓冲、换隧道类型也没用：如实说这条隧道不适合，可换 frp 或两条隧道，不写「已修复」。
- 账号、authtoken、后台密码只在当次用，用完不留存、不写进记录、不在回复里复述。
