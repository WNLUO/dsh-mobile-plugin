# frp 自建公网直连

自己有一台带公网 IP 的服务器时，可以用 frp 把电脑上的服务端口搬到公网，手机拨你自己的 frps，不必用官方中转。frp 是纯 TCP 转发，SSE / WebSocket 原样穿过，比会缓冲响应的 web 隧道省心。它顶替的是中转，不是新功能——鉴权和配对还在电脑这侧。共用的栏位、DDNS、反代、验收见 `references/selfhost-common.md`。

## 先认清自己站哪边

- 跑在用户电脑上、有本机 shell —— 执行者：自己查 frpc 状态、自己 curl 公网地址验体检口和鉴权。
- 回反馈、够不着用户那台电脑 —— 指导者：一步一步说给用户做，请他回报结果，不谎称自己起过隧道。

## 开查前先问一句（话要短）

「服务器有公网 IP 吗？有域名和证书吗？frpc 跑起来了吗？」能直接答就往下走；不清楚再要相关信息，别上来一大段。

## 选哪一档

- **有域名 + 证书：走 https 隧道（优先）。** frps 在公网 443 用证书终结 TLS，frpc 用 `type=https` + `customDomains` 把电脑的 `18787` 映射到域名。手机填 `https://域名` 到直连地址栏。这一档手机侧是 https，凭据不会被链路上的人看到。
- **只有公网 IP、没域名证书：走裸 TCP 兜底。** frpc 用 `type=tcp` 把 `18787` 映射到公网某个端口。手机填 `http://公网IP:端口`。代价要当面说清：公网这段是明文，配对令牌和请求头里的凭据会被看到；请求正文本身还有一层端到端加密，裸的是元数据和凭据这一层。iOS 上别写 `http://域名:端口` 这种明文域名，会触发系统的明文限制；用 IP:端口，或回到 https 那档。

**关键一点别搞错**：手机侧的加密靠 frps 在公网口终结 TLS（https 那档），不是 frp 隧道内部那条 `transport.tls`——后者只保护 frpc↔frps 那一段。想要手机侧加密就必须让手机连的是 https 地址。

## 电脑这侧怎么起隧道

- 配好 frps（公网服务器）和 frpc（跑 DSH 的电脑），token 两端一致。frpc 的本地端口填插件实际监听的端口，默认 `18787`，改过就以状态里报的实绑端口为准。
- 面板上有「导入 frpc 配置」：把配置贴进去，插件会自动把 `localPort` 对齐到此刻真实监听端口再起 frpc，不让你手填的端口和实例错开。导入后可以填进直连地址或 TCP 直连栏（看配置类型）；详情和运行状态在 `/api/relay/status` 的 `frp` 那格。
- 起不来先看 frpc 有没有装（可选依赖、平台对不对）、token 和端口对不对、服务器上防火墙/安全组有没有放那个端口。别把"填了地址"当成"隧道在转发"。
- 要停隧道路面板上有停止动作；只是不想用了就停掉，别只删地址留个进程在跑。

## 填哪个栏

- https 那档（域名）→ 直连地址栏填 `https://域名`。
- 裸 TCP 那档 → 按配置类型填直连地址（`http://IP:端口`）或 TCP 直连（`主机:端口`）；别同时填两个。
- 别填进 IPv6 栏，那是另一条通道。

## 上手机前验收

按 `references/selfhost-common.md` 四条过一遍：体检口 `curl https://域名/api/mobile/v1/health` 回带 service 和版本的 JSON；不带 token 访问 `/status` 回 401；手机流量下实测 SSE 流式和大文件上传。frp 的 tcp 一般不缓冲，反而比 web 隧道稳；卡住就查服务器到主机这段。

## 几个坑

- 一条 frp 代理对应一个本地端口，多台电脑各配各的。
- 域名别到处贴：拿到域名的人能试着配对，好在配对码有限流、控制面被挡；想更保险就关掉中转只留这条直连，并定期轮换配对码。
- https 那档依赖域名和证书续期；证书过期手机就连不上，把续期自动化。
- 公网 IP 会变：没域名就跟着改地址，有域名配 DDNS 自动追（见共用篇）。
- 电脑侧面板只报「设备数 / 最后在线」，终判认手机断 Wi-Fi 走流量实测。

## 什么时候停

- 没公网服务器、又不想养一台：如实说 frp 这条路不适合，指去 natapp 或两条隧道，不写「已修复」。
- 隧道起了但实测不通、查不出原因：把卡在哪一步（frpc 状态 / 体检口 / 鉴权 / 流式）说清，标「待定位」，别假装查完。
- 公网那段要明文的取舍让用户自己拍板，别替他决定降不降级。
