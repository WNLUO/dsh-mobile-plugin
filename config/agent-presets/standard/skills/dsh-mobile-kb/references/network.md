# 选路：局域网 / 直连 / 中转 / IPv6

App 到电脑之间有好几条路，用户说「连不上」时，先确认他选的是哪条、那条路本身通不通。

> **公用中转已正式下线、不再可用**：升级后老配置里的内置地址会被清掉，面板里的相关入口和线路档位也已移除。别再把它当兜底或推荐；遇到旧地址、旧域名或报障，直接引导用户用局域网、自建中转、内置隧道或第三方线路（见 `references/relay.md`、`references/network-guide.md`）。

## 几种模式

- `auto`（缺省）：局域网优先，失败按各通道自己的退避窗口退到公网线路（自建中转、内置隧道或第三方线路）。大多数用户用这个。
- `lan`：只走局域网，同一 Wi-Fi 才通；人在外面就是连不上，这是选择本身。
- `direct`：只走「直连地址」那一格——用户手填的公网 IP 或内网穿透域名，不走局域网发现。
- `wan`：只走服务器中转，局域网与 IPv6 都不碰。
- `ipv6`：只走 IPv6 直连，局域网与中转都不碰；进不来就是连不上。

「局域网地址」和「直连地址」是两栏配置、两个档位，别混着说。手机侧栏写「直连」时，要分清指局域网直连还是公网直连。

## 三条内置隧道默认开

tailcat 直连隧道、P2P 隧道、Cloudflare 快隧道都在面板里，出厂默认开启；用户主动关掉某条后才会保持关闭。用户说「连不上」时先看开关状态：那条是不是被人关过；三条开着仍不通才是线路问题。开哪条、要不要关掉其中一条，按 `references/network-guide.md` 按条件挑，别上来就让用户改。tailcat 和 P2P 开了还要配对才通，P2P 打洞失败没有中转兜底；Cloudflare 国内常连不上，开着会占住「直连地址」那一格，说清这点再让用户决定要不要关。

## 常见误区

- 弱网或切换网络后，上传、下载、图片会自行重试并排队；正常恢复期间的状态变化不一定是故障。
- 换网络后网段变了，旧的局域网候选地址全是死的，要重算；不要让用户反复点重连。
- 局域网刚探通、中转刚搬家、隧道刚起来，内核会换候选顺序，但不停现有连接——界面未必立刻跟上。

## 给用户的信息清单

版本与构建号、选路模式、三条隧道各自的开关状态、局域网与直连地址栏各填了什么、是否同一 Wi-Fi、最近有没有换网络、网络诊断页的展开结果。

## 边界

排查阶段只读只看，不替用户改模式、不重启服务。多处信息矛盾又查不出原因的，标「待定位」，请用户补网络诊断现场，不写「已修复」。
